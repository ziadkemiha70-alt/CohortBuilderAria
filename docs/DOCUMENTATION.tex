\section{Objectif du document}

Ce document décrit l'organisation et l'utilisation du dépôt \code{ARIA ODM Builder}.

Il complète le diaporama placé dans le dossier \code{docs/}. Le diaporama sert de vue d'ensemble rapide et visuelle. La présente documentation sert de référence plus détaillée pour comprendre les fichiers, exécuter le pipeline et maintenir le projet.

\medskip

Le projet vise à construire une chaîne de traitement permettant de transformer des extractions issues d'ARIA en exports patients structurés, contrôlés et traçables pour un usage de recherche clinique.

\subsection*{À retenir}

\begin{itemize}
  \item le diaporama explique l'architecture générale du dépôt ;
  \item cette documentation explique plus précisément les dossiers, fichiers et commandes ;
  \item le workflow complet suit la logique :
\end{itemize}

\begin{lstlisting}
Extraction SQL
    -> scripts de préparation
    -> fichiers préparés
    -> configuration
    -> application Streamlit
    -> contrôles qualité
    -> export final
\end{lstlisting}

% ============================================================
\section{Vue d'ensemble du workflow}

Le pipeline est organisé en plusieurs étapes successives.

\begin{enumerate}
  \item Exécuter les requêtes SQL nécessaires à l'extraction des données.
  \item Préparer ou harmoniser les fichiers avec les scripts du dossier \code{scripts/}.
  \item Charger les fichiers préparés dans l'application Streamlit.
  \item Appliquer le mapping et le profil JSON.
  \item Construire la cohorte.
  \item Calculer les variables temporelles et les variables d'intérêt.
  \item Contrôler la qualité des jointures, des dates et des champs exportés.
  \item Générer un export final et un rapport de contrôle.
\end{enumerate}

\begin{lstlisting}
sql/
  -> scripts/load_final_all.py
      -> inputs/ ou fichiers sources préparés
          -> app.py
              -> utils/
                  -> outputs/
\end{lstlisting}

Cette organisation permet de distinguer clairement :
\begin{itemize}
  \item l'extraction des données ;
  \item leur préparation ;
  \item leur traitement dans l'interface ;
  \item la production d'un résultat contrôlé.
\end{itemize}

\section{Application Streamlit}

\subsection{Rôle de \code{app.py}}

Le fichier \code{app.py} est le point d'entrée principal de l'application.

Il contient notamment :
\begin{itemize}
  \item la configuration de l'interface ;
  \item les onglets de navigation ;
  \item les zones d'import ;
  \item les boutons de recalcul ;
  \item l'enchaînement général du workflow ;
  \item l'appel aux modules du dossier \code{utils/}.
\end{itemize}

L'application se lance avec :

\begin{lstlisting}
streamlit run app.py
\end{lstlisting}

Une fois lancée, elle s'ouvre dans le navigateur.

\subsection{Organisation logique de l'interface}

L'interface peut être organisée en plusieurs onglets :

\begin{lstlisting}
Accueil -> Import -> Construction -> Controle qualite -> Sources -> Profil
\end{lstlisting}

\begin{longtable}{p{0.25\linewidth} p{0.68\linewidth}}
\toprule
\textbf{Onglet} & \textbf{Rôle} \\
\midrule
\endhead

Accueil &
Présente l'objectif de l'application et le workflow général. \\

Import &
Permet de charger les fichiers sources, le mapping et éventuellement un profil JSON. \\

Construction &
Permet de choisir les critères de cohorte, les variables et de lancer le calcul. \\

Contrôle qualité &
Affiche les contrôles principaux : jointures, dates, doublons, valeurs manquantes ou incohérentes. \\

Sources &
Documente l'origine des colonnes générées et des variables utilisées. \\

Profil &
Permet de sauvegarder ou réimporter une configuration au format JSON. \\

\bottomrule
\end{longtable}

\section{Configuration du pipeline}

\subsection{Dossier \code{conf/}}

Le dossier \code{conf/} contient les fichiers qui pilotent le comportement du pipeline.

\begin{lstlisting}
conf/
|-- mapping.csv
`-- profiles/
    `-- Prostate.json
\end{lstlisting}

\subsection{Fichier \code{mapping.csv}}

Le fichier \code{mapping.csv} associe les colonnes présentes dans les fichiers sources aux variables utilisées dans le pipeline.

Il peut contenir par exemple :
\begin{itemize}
  \item les codes CIM10 ;
  \item les localisations ;
  \item les libellés de variables ;
  \item les requêtes ou champs d'intérêt ;
  \item les phases temporelles ;
  \item des commentaires utiles à la sélection.
\end{itemize}

Format indicatif :

\begin{lstlisting}
CIM10;Description;Localisation;Requete;Phase;Commentaire
C61;Tumeur maligne de la prostate;Prostate;PSA;Cumul;
C61;Tumeur maligne de la prostate;Prostate;Dysurie;Aigu;
\end{lstlisting}

\subsection{Profils JSON}

Les profils JSON servent à sauvegarder une configuration d'extraction.

Ils peuvent contenir :
\begin{itemize}
  \item les colonnes sélectionnées ;
  \item les critères de cohorte ;
  \item les temporalités choisies ;
  \item les paramètres de fenêtre ;
  \item les choix d'export ;
  \item les noms de fichiers ou options de traitement.
\end{itemize}

Exemple :

\begin{lstlisting}
conf/profiles/Prostate.json
\end{lstlisting}

\subsection*{Principe simple}

\begin{center}
\textbf{Le mapping indique où lire les données. Le profil indique quoi sélectionner.}
\end{center}

\section{Fichiers d'entrée attendus}

L'application utilise principalement trois types de fichiers sources :

\begin{longtable}{p{0.25\linewidth} p{0.68\linewidth}}
\toprule
\textbf{Fichier} & \textbf{Rôle} \\
\midrule
\endhead

\code{source\_A.csv} &
Fichier principal de traitement. Il contient les informations nécessaires à la construction de la base patient et de la cohorte. \\

\code{source\_B.csv} &
Fichier de formulaires cliniques ou d'informations longitudinales. \\

\code{source\_C.csv} &
Fichier complémentaire optionnel, par exemple un flux adaptatif ou une source annexe. \\

\code{mapping.csv} &
Fichier de configuration permettant de relier les colonnes sources aux variables attendues. \\

\code{profil JSON} &
Fichier permettant de sauvegarder et réutiliser une configuration d'extraction. \\

\bottomrule
\end{longtable}

\subsection{Colonnes indicatives pour le fichier de traitement}

Le fichier de traitement doit permettre d'identifier les patients et les principales informations de traitement.

Colonnes attendues ou détectées selon le mapping :
\begin{itemize}
  \item identifiant patient ;
  \item code diagnostique ou code CIM10 ;
  \item date de première fraction ;
  \item date de dernière fraction ;
  \item dose ;
  \item nombre de fractions ;
  \item technique ou machine, si disponible et utile.
\end{itemize}

\subsection{Colonnes indicatives pour le fichier de formulaires}

Le fichier de formulaires doit contenir des informations cliniques datées.

Colonnes attendues ou détectées selon le mapping :
\begin{itemize}
  \item identifiant patient ;
  \item date de l'événement ou du formulaire ;
  \item variables cliniques ou champs de formulaire à exploiter.
\end{itemize}

\section{Installation}

\subsection{Se placer dans le dossier du projet}

Dans un terminal :

\begin{lstlisting}
cd chemin/vers/ARIA_ODM_Builder
\end{lstlisting}

\subsection{Créer un environnement Python}

Commande recommandée :

\begin{lstlisting}
python -m venv .venv
\end{lstlisting}

Activation sous Windows :

\begin{lstlisting}
.venv\Scripts\activate
\end{lstlisting}

Activation sous macOS ou Linux :

\begin{lstlisting}
source .venv/bin/activate
\end{lstlisting}

\subsection{Installer les dépendances}

Commande standard :

\begin{lstlisting}
pip install -r requirements.txt
\end{lstlisting}

Si \code{pip} n'est pas reconnu :

\begin{lstlisting}
python -m pip install -r requirements.txt
\end{lstlisting}

\section{Lancement de l'application}

Commande standard :

\begin{lstlisting}
streamlit run app.py
\end{lstlisting}

Commande alternative :

\begin{lstlisting}
python -m streamlit run app.py
\end{lstlisting}

Après exécution, l'application s'ouvre dans le navigateur.

\subsection{Utilisation résumée}

\begin{enumerate}
  \item Lancer l'application.
  \item Importer les fichiers sources.
  \item Vérifier ou charger le mapping.
  \item Sélectionner un profil JSON ou configurer l'extraction.
  \item Construire la cohorte.
  \item Lire le rapport qualité.
  \item Exporter le résultat.
\end{enumerate}

\section{Contrôles qualité}

Les contrôles qualité servent à vérifier que le pipeline a correctement chargé, relié et transformé les données.

Ils peuvent porter sur :
\begin{itemize}
  \item la présence des colonnes attendues ;
  \item les jointures entre les fichiers ;
  \item les dates de début et de fin ;
  \item les doublons ;
  \item les valeurs manquantes ;
  \item les valeurs distinctes observées ;
  \item les variables réellement exportées.
\end{itemize}

\subsection{Rapport de preuve}

Le rapport de preuve doit aider l'utilisateur à comprendre :
\begin{itemize}
  \item quels fichiers ont été chargés ;
  \item quels paramètres ont été utilisés ;
  \item quelles transformations ont été appliquées ;
  \item quels contrôles ont été réalisés ;
  \item quelles sorties ont été produites.
\end{itemize}
