# Quality controls and evidence report

## 1. Purpose

Quality controls describe the technical and structural coherence of the generated cohort. They focus on source matching, reference-date availability, duplicates, treatment-value multiplicity and output structure. They do not replace domain review of the resulting variables.

## 2. Main quality metrics

The quality table may include:

- treatment patients found in the form source;
- selected cohort patients found in the form source;
- availability of `startD` and `endD`;
- number of selected variables;
- number of form observations retained;
- exact duplicate count;
- non-interpretable form dates;
- patient distribution by treatment source;
- multiple distinct doses, dates, fractions or machines for one patient.

Statuses are reported as `OK`, `Info` and `A vérifier`. The French status text is preserved because it is generated by the current application.

## 3. Treatment coherence checks

For each patient, the application may flag multiple distinct values for:

- first-fraction date;
- last-fraction date;
- delivered dose;
- number of fractions;
- treatment machine.

Technique is not included in this specific multiplicity rule because more than one technique can legitimately belong to a single treatment history.

A warning does not automatically mean that the patient must be removed. It indicates that the row-level source cannot be represented unambiguously by a single patient-level value without review.

## 4. Evidence workbook contents

The evidence workbook may contain the following sheets:

| Sheet | Content |
|---|---|
| `Pipeline` | processing steps and construction parameters |
| `Resume` | main export metrics |
| `Qualite` | quality-control results |
| `Distribution_CIM10` | row and patient counts by normalised ICD-10 code |
| `Selection_colonnes` | selected variables and observed coverage |
| `Schema_colonnes` | generated ODM/export columns |
| `Colonnes_100pct_NA` | columns without any value in the cohort |
| `Aide_mapping` | mapping-derived correspondences |
| `Skrub_nettoyage` | controlled cleaning operations |
| `Ethos_integration` | ETHOS-integration summary |
| `Traitement_incoherences` | details of multiple treatment values |
| `Doublons_exact_sample` | sample of exact duplicates |
| `Formulaire_long_sample` | sample of prepared long-format observations |
| `Profiling` | stage durations when profiling is enabled |

Sheet names are implementation identifiers and are not translated.

## 5. Recommended review sequence

Before using an export:

1. confirm the expected number of unique patients;
2. review treatment-to-form matching rates;
3. verify `startD` and `endD` availability;
4. inspect patients with multiple treatment values;
5. review entirely empty output columns;
6. inspect unmatched profile variables;
7. compare a small traceability sample with the intended source behaviour;
8. retain the evidence workbook with the final export.

## 6. Interpreting common findings

- A low treatment-to-form match rate may indicate incompatible patient identifiers or a cohort with limited form coverage.
- Missing `startD` or `endD` prevents reliable temporal classification for the affected patient.
- Multiple dose or machine values may represent several treatment courses, source duplication or legitimate complexity.
- A `100% NA` column may be structurally correct but unpopulated in the selected cohort and windows.
- Exact duplicates may be harmless source repetition, but their volume should be understood before removal.
